# D2C 结构转换 Agent 设计

结构转换 Agent 是 D2C 流水线的第二个阶段。它接收清洗后的 Figma 节点数据，将设计工具中的节点、布局和样式转换为统一的组件 DSL（Domain-Specific Language，领域专用语言）。

```text
清洗后的 Figma 数据 -> 结构转换 Agent -> 组件 DSL
```

## 一、为什么清洗后的数据还不能直接生成代码

数据清洗解决的是冗余问题，但清洗后的数据仍然使用 Figma 的表达方式。例如：

- `FRAME` 表示容器，但不明确它应该生成页面、区块还是普通 `div`
- `TEXT` 只表示文本节点，不包含业务组件语义
- 自动布局描述的是设计工具行为，不完全等同于 CSS
- 组件实例可能带有复杂的引用和覆盖关系

如果让代码生成模型直接理解这些节点，每次生成都需要重新完成“设计节点到前端组件”的推断，结果容易不一致。

## 二、为什么需要 DSL

DSL 是设计数据和前端代码之间的稳定中间层。

```text
Figma 节点 -> 组件 DSL -> React / Vue / HTML
```

它将不同框架共有的信息提取出来，例如：

```json
{
  "type": "Button",
  "props": {
    "variant": "primary",
    "text": "提交"
  },
  "layout": {
    "width": 120,
    "height": 40
  }
}
```

有了 DSL，同一份设计结构可以生成 React、Vue 或其他目标代码，而不需要重复解析 Figma。

## 三、结构转换 Agent 的设计目标

1. 将 Figma 节点映射为前端组件概念
2. 还原父子关系和页面层级
3. 将自动布局转换为通用布局描述
4. 提取组件属性、文本内容和视觉样式
5. 为知识检索和代码生成提供稳定输入

常见映射关系如下：

| Figma 节点 | DSL 组件 |
| --- | --- |
| `FRAME` | `Page`、`Container`、`Section` |
| `TEXT` | `Text`、`Heading`、`Label` |
| `RECTANGLE` | `Box`、`Image`、`Divider` |
| `COMPONENT` / `INSTANCE` | 可复用业务组件 |

## 四、为什么单独设计这一阶段

结构转换本质上是确定性的语义归一化。如果把它合并进代码生成阶段：

- 模型每次都需要重新理解 Figma 节点
- React 和 Vue 的生成逻辑会重复处理相同结构
- 很难检查错误究竟来自设计解析还是代码生成
- 无法方便地替换代码生成模型

独立 DSL 让每个阶段职责清晰，也让中间结果可以被测试、缓存和人工检查。

## 五、为什么优先使用规则引擎

节点映射、布局换算和树结构转换存在大量明确规则，使用普通程序更稳定：

- 相同节点始终得到相同 DSL
- 转换规则容易单元测试
- 不产生额外模型调用成本
- 出错时可以定位到具体节点和规则
- 不会因为提示词变化导致结构漂移

对于难以通过规则识别的业务语义，可以后续增加模型分类，但不应让大模型替代所有基础转换。

## 六、失败风险与验证方式

常见失败包括：

- 错误识别容器和组件
- 丢失节点层级
- 将横向布局转换为纵向布局
- 忽略组件实例的属性覆盖
- 过度使用绝对定位

可以通过 DSL Schema 校验、节点数量对比、布局快照和典型组件测试集验证转换质量。

## 总结

结构转换 Agent 的作用，是将 Figma 的设计工具语言转换为前端系统能够稳定理解的组件语言。它隔离了设计数据与目标框架，使后续知识检索和代码生成不必反复处理复杂的 Figma 原始结构。
