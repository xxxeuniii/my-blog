# 浏览器存储

浏览器提供了 Cookie、Web Storage、IndexedDB 和 Cache Storage 等存储能力。它们在容量、生命周期、数据类型和使用场景上各不相同。

## 存储方式对比

| 存储方式 | 数据类型 | 容量 | 生命周期 | 适合场景 |
| --- | --- | --- | --- | --- |
| Cookie | 字符串 | 很小 | 可设置过期时间 | 会话标识、小量服务端数据 |
| sessionStorage | 字符串 | 较小 | 标签页关闭后清除 | 单次页面会话数据 |
| localStorage | 字符串 | 较小 | 主动清除前一直存在 | 简单配置、主题偏好 |
| Cache Storage | Request / Response | 较大 | 主动清除前一直存在 | 缓存请求与静态资源 |
| IndexedDB | 结构化数据、Blob | 较大 | 主动清除前一直存在 | 离线数据和复杂本地数据 |

## Cookie

Cookie 是由浏览器保存的小段字符串数据。符合域名、路径等规则的 Cookie 会自动随 HTTP 请求发送到服务端。

```js
// 写入 Cookie
document.cookie = 'theme=dark; max-age=86400; path=/; SameSite=Lax'

// 读取当前页面可访问的 Cookie
console.log(document.cookie)
```

常见安全属性：

- `HttpOnly`：禁止 JavaScript 读取，只能由服务端设置。
- `Secure`：仅通过 HTTPS 传输。
- `SameSite`：限制跨站请求携带 Cookie，降低 CSRF 风险。

Cookie 容量较小，并会增加请求体积，不适合存储大量业务数据。

## localStorage

`localStorage` 用于持久化保存少量字符串数据，关闭浏览器后数据仍然存在。

```js
localStorage.setItem('theme', 'dark')

const theme = localStorage.getItem('theme')

localStorage.removeItem('theme')
localStorage.clear()
```

存储对象时需要手动序列化：

```js
const user = { id: 1, name: 'Eunie' }

localStorage.setItem('user', JSON.stringify(user))

const savedUser = JSON.parse(localStorage.getItem('user') ?? 'null')
```

`localStorage` 是同步 API，大量读写会阻塞主线程，不适合保存大量数据。

## sessionStorage

`sessionStorage` 的 API 与 `localStorage` 相同，但数据仅在当前标签页会话中有效。

```js
sessionStorage.setItem('form-step', '2')
sessionStorage.getItem('form-step')
sessionStorage.removeItem('form-step')
```

它适合保存多步骤表单进度、当前标签页临时状态等数据。

## IndexedDB

IndexedDB 是浏览器内置的 NoSQL 数据库，适合持久化存储大量结构化数据、文件和二进制内容。

```js
console.log(window.indexedDB)
```

适用场景：

- 保存离线应用数据
- 缓存大量接口响应
- 保存尚未提交的编辑内容
- 存储图片、音频等 `Blob` 数据
- 为 PWA 提供本地数据能力

IndexedDB 中的数据保存在用户浏览器内，不会自动同步到服务端，也不能代替服务端数据库。

### IndexedDB 核心概念

| 概念 | 说明 |
| --- | --- |
| Database | 数据库，一个站点可以创建多个数据库 |
| Object Store | 对象仓库，类似关系型数据库中的表 |
| Record | 存储在对象仓库中的一条数据 |
| Key | 唯一标识一条数据的主键 |
| Index | 根据指定字段快速查询数据 |
| Transaction | 事务，所有读写操作都必须在事务中执行 |
| Version | 数据库版本，用于升级数据库结构 |

### 打开数据库

```js
const request = indexedDB.open('my-app', 1)

request.onupgradeneeded = event => {
  const db = event.target.result

  if (!db.objectStoreNames.contains('users')) {
    const store = db.createObjectStore('users', {
      keyPath: 'id',
      autoIncrement: true
    })

    store.createIndex('email', 'email', { unique: true })
    store.createIndex('name', 'name', { unique: false })
  }
}

request.onsuccess = event => {
  const db = event.target.result
  console.log('数据库打开成功', db)
}

request.onerror = event => {
  console.error('数据库打开失败', event.target.error)
}
```

`onupgradeneeded` 会在首次创建数据库或版本号增加时触发。创建对象仓库和索引等结构变更必须在这里完成。

### 增删改查

所有操作都需要先创建事务，再获取对象仓库。

```js
const transaction = db.transaction('users', 'readwrite')
const store = transaction.objectStore('users')

// 新增
store.add({
  name: 'Eunie',
  email: 'eunie@example.com'
})

// 修改或新增
store.put({
  id: 1,
  name: 'Eunie Updated',
  email: 'eunie@example.com'
})

// 根据主键查询
const getRequest = store.get(1)
getRequest.onsuccess = () => console.log(getRequest.result)

// 根据主键删除
store.delete(1)
```

### 使用索引查询

```js
const transaction = db.transaction('users', 'readonly')
const store = transaction.objectStore('users')
const emailIndex = store.index('email')
const request = emailIndex.get('eunie@example.com')

request.onsuccess = () => {
  console.log(request.result)
}
```

### 查询全部数据与游标

```js
// 一次读取全部数据
store.getAll()

// 使用游标逐条读取
const request = store.openCursor()

request.onsuccess = event => {
  const cursor = event.target.result

  if (cursor) {
    console.log(cursor.key, cursor.value)
    cursor.continue()
  }
}
```

数据量很大时应使用游标分批处理，避免一次读取全部数据。

### 使用 Promise 封装

IndexedDB 原生 API 基于事件，可以封装为 Promise 方便配合 `async/await` 使用。

```js
function openDatabase() {
  return new Promise((resolve, reject) => {
    const request = indexedDB.open('my-app', 1)

    request.onupgradeneeded = event => {
      const db = event.target.result

      if (!db.objectStoreNames.contains('users')) {
        db.createObjectStore('users', {
          keyPath: 'id',
          autoIncrement: true
        })
      }
    }

    request.onsuccess = () => resolve(request.result)
    request.onerror = () => reject(request.error)
  })
}

const db = await openDatabase()
```

复杂项目也可以使用 `idb`、Dexie.js 等库简化 IndexedDB 操作。

### 数据库版本升级

数据库结构发生变化时，需要增加版本号：

```js
const request = indexedDB.open('my-app', 2)

request.onupgradeneeded = event => {
  const db = event.target.result
  const transaction = event.target.transaction

  if (event.oldVersion < 1) {
    db.createObjectStore('users', {
      keyPath: 'id',
      autoIncrement: true
    })
  }

  if (event.oldVersion < 2) {
    const store = transaction.objectStore('users')
    store.createIndex('email', 'email', { unique: true })
  }
}
```

生产项目应保留每个版本的升级逻辑，确保老用户能够平滑升级数据库结构。

## Cache Storage

Cache Storage 用于保存网络请求和响应，通常与 Service Worker 配合实现离线访问。

```js
const cache = await caches.open('app-cache-v1')

await cache.add('/index.html')
await cache.addAll(['/app.js', '/style.css'])

const response = await cache.match('/index.html')

await cache.delete('/index.html')
```

Cache Storage 适合缓存静态资源和接口响应，不适合当作通用结构化数据库。

## 如何选择

| 需求 | 推荐方式 |
| --- | --- |
| 服务端需要自动接收的数据 | Cookie |
| 保存主题、语言等简单配置 | localStorage |
| 保存当前标签页临时状态 | sessionStorage |
| 保存大量结构化或离线数据 | IndexedDB |
| 缓存请求响应和静态资源 | Cache Storage |

## 注意事项

- 浏览器存储通常遵循同源策略，不同域名、协议或端口无法直接共享数据。
- 不要在浏览器存储中保存密码、令牌等未加密敏感数据。
- 用户清除网站数据时，相关浏览器存储也会被删除。
- 浏览器可能回收长期未使用站点的数据，关键数据必须同步到服务端。
- `localStorage` 和 `sessionStorage` 是同步 API，应避免大量读写。
- IndexedDB 所有读写操作都需要通过事务执行。
- 可以在浏览器开发者工具的 `Application` 面板中查看和调试存储数据。

## IndexedDB 常见错误

| 错误 | 常见原因 |
| --- | --- |
| `ConstraintError` | 主键或唯一索引重复 |
| `NotFoundError` | 对象仓库或索引不存在 |
| `TransactionInactiveError` | 事务已经完成或失效 |
| `VersionError` | 打开的版本号低于现有数据库版本 |
| `QuotaExceededError` | 超出浏览器允许的存储容量 |
