# 测试用例设计

## 一、什么是测试用例

测试用例是对软件测试目的、测试步骤、预期结果的描述。

### 测试用例要素

| 要素 | 说明 |
|------|------|
| **用例编号** | 唯一标识 |
| **用例名称** | 简要描述 |
| **前置条件** | 执行前需要满足的条件 |
| **测试步骤** | 具体操作步骤 |
| **测试数据** | 输入数据 |
| **预期结果** | 期望的输出 |
| **优先级** | 重要程度 |

---

## 二、测试用例设计方法

### 2.1 等价类划分

**原理**：将输入数据划分为若干等价类，从每个等价类中选取代表性数据进行测试。

**分类**：
- **有效等价类**：合理的、有意义的输入数据
- **无效等价类**：不合理的、无意义的输入数据

**示例**：用户名输入（6-18位字符）

```
有效等价类：6-18位字符
无效等价类：< 6位、> 18位、特殊字符、空

测试数据：
- 有效：6位、10位、18位
- 无效：5位、19位、含特殊字符、空字符串
```

### 2.2 边界值分析

**原理**：错误经常发生在边界值附近，需要重点测试边界值。

**边界值选取**：
- 最小值、最小值-1、最小值+1
- 最大值、最大值-1、最大值+1
- 正常值

**示例**：年龄输入（18-60岁）

| 测试数据 | 边界类型 | 预期结果 |
|----------|----------|----------|
| 17 | 下边界-1 | 无效 |
| 18 | 下边界 | 有效 |
| 19 | 下边界+1 | 有效 |
| 30 | 正常值 | 有效 |
| 59 | 上边界-1 | 有效 |
| 60 | 上边界 | 有效 |
| 61 | 上边界+1 | 无效 |

### 2.3 因果图法

**原理**：分析输入条件（因）和输出结果（果）之间的关系。

**步骤**：
1. 分析所有输入条件和输出结果
2. 找出条件和结果之间的因果关系
3. 画出因果图
4. 转换为判定表
5. 设计测试用例

**示例**：订单优惠

```
条件：
C1: 会员等级 = 黄金
C2: 订单金额 > 1000

结果：
E1: 享受8折优惠
E2: 享受9折优惠
E3: 无优惠

关系：
C1 AND C2 → E1
NOT C1 AND C2 → E2
NOT C2 → E3
```

### 2.4 判定表法

**原理**：列出所有可能的条件组合，确保每种组合都被测试到。

**示例**：文件修改权限

| 条件 | 规则1 | 规则2 | 规则3 | 规则4 |
|------|-------|-------|-------|-------|
| 是管理员 | Y | N | N | N |
| 是所有者 | - | Y | N | N |
| 有写权限 | - | - | Y | N |
| **允许修改** | Y | Y | Y | N |

### 2.5 场景法

**原理**：基于业务场景设计测试用例，模拟真实用户操作。

**场景类型**：
- **基本流**：正常的业务流程
- **备选流**：异常或备选的业务流程

**示例**：用户登录

```
基本流：
1. 打开登录页面
2. 输入正确的用户名和密码
3. 点击登录
4. 登录成功，跳转首页

备选流：
1. 用户名或密码为空
2. 用户名不存在
3. 密码错误
4. 账号被锁定
5. 网络异常
```

### 2.6 错误推测法

**原理**：根据经验推测可能出错的地方，设计测试用例。

**常见错误点**：
- 空值/null
- 特殊字符
- 超长输入
- 重复提交
- 并发操作
- 网络超时

## 三、测试用例设计原则

### 3.1 SMART 原则

| 原则 | 说明 |
|------|------|
| **S**pecific | 具体明确 |
| **M**easurable | 可度量 |
| **A**chievable | 可实现 |
| **R**elevant | 相关性 |
| **T**ime-bound | 有时限 |

### 3.2 设计原则

1. **完整性**：覆盖所有功能点
2. **独立性**：测试用例之间相互独立
3. **可重复性**：可以重复执行
4. **可维护性**：易于维护和更新
5. **清晰性**：步骤和预期结果清晰

## 四、测试用例示例

### 示例：用户注册功能

| 用例编号 | TC_REG_001 |
|----------|------------|
| 用例名称 | 正常注册 |
| 优先级 | 高 |
| 前置条件 | 用户未登录 |
| 测试步骤 | 1. 打开注册页面<br>2. 输入用户名：testuser<br>3. 输入密码：Test@123<br>4. 确认密码：Test@123<br>5. 输入邮箱：test@example.com<br>6. 点击注册按钮 |
| 预期结果 | 1. 注册成功<br>2. 提示"注册成功"<br>3. 跳转到登录页面 |

| 用例编号 | TC_REG_002 |
|----------|------------|
| 用例名称 | 用户名已存在 |
| 优先级 | 中 |
| 前置条件 | 用户名 testuser 已注册 |
| 测试步骤 | 1. 打开注册页面<br>2. 输入用户名：testuser<br>3. 输入其他信息<br>4. 点击注册按钮 |
| 预期结果 | 提示"用户名已存在" |

## 五、测试用例管理

### 5.1 优先级划分

| 优先级 | 说明 | 示例 |
|--------|------|------|
| **P0** | 最高优先级，核心功能 | 登录、支付 |
| **P1** | 高优先级，重要功能 | 搜索、下单 |
| **P2** | 中优先级，一般功能 | 个人设置 |
| **P3** | 低优先级，次要功能 | 帮助页面 |

### 5.2 测试用例评审

评审要点：
- 是否覆盖所有需求
- 是否有冗余或遗漏
- 预期结果是否正确
- 是否可执行
- 是否有足够的异常场景

---

## 总结

测试用例设计是测试活动的核心，常用方法包括：

| 方法 | 适用场景 |
|------|----------|
| **等价类划分** | 输入数据分类 |
| **边界值分析** | 边界值测试 |
| **因果图法** | 条件组合关系 |
| **判定表法** | 多条件组合 |
| **场景法** | 业务流程测试 |
| **错误推测法** | 经验性测试 |

选择合适的方法，设计高质量的测试用例，是保证测试效果的关键。
