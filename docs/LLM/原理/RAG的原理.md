# RAG 的原理

RAG（Retrieval-Augmented Generation，检索增强生成）是一种让大语言模型在回答问题前，先从外部知识库中检索相关资料，再结合资料生成答案的技术。

它解决的核心问题是：**模型参数中的知识有限、可能过时，而且模型可能在不知道答案时产生幻觉。**

## 一、RAG 的核心思想

普通大模型直接根据问题生成答案：

```text
用户问题 -> 大语言模型 -> 答案
```

RAG 在模型回答前增加了检索过程：

```text
用户问题 -> 检索相关资料 -> 将资料和问题交给大模型 -> 答案
```

大模型不需要记住全部业务知识，而是像参加开卷考试一样，先查资料，再组织答案。

## 二、RAG 的完整流程

RAG 系统通常分为离线索引和在线问答两个阶段。

### 1. 离线索引

离线阶段负责把原始文档转换成可检索的知识库。

```text
原始文档
  -> 解析与清洗
  -> 文本分块
  -> Embedding 向量化
  -> 存入向量数据库
```

#### 文档解析

系统读取 PDF、网页、Markdown、数据库记录等数据，并保留标题、来源、更新时间和权限等元数据。

#### 文本分块

Embedding 模型和大模型都有上下文长度限制，因此需要将长文档拆成较小的 Chunk。

分块太大，会包含过多无关内容；分块太小，又可能破坏完整语义。实际系统通常结合标题、段落、语义边界和一定的重叠区间进行分块。

#### Embedding 向量化

Embedding 模型会把文本映射为高维向量：

```text
"如何重置密码" -> [0.12, -0.38, 0.91, ...]
```

语义相近的文本，其向量在空间中的距离也更近。向量数据库保存这些向量及其对应的原文和元数据。

### 2. 在线问答

用户提问时，系统执行以下过程：

```text
用户问题
  -> 问题改写与向量化
  -> 召回候选文档
  -> 重排序与过滤
  -> 组装上下文
  -> 大模型生成答案
```

#### 查询向量化

系统使用与知识库相同的 Embedding 模型，将用户问题转换为向量。

#### 相似度检索

向量数据库计算问题向量与文档向量的相似度，常见方法包括余弦相似度、点积和欧氏距离。

余弦相似度关注两个向量的方向：

```text
cosine_similarity(q, d) = (q · d) / (|q| × |d|)
```

相似度越高，通常表示文档与问题越相关。

#### 重排序

向量检索速度快，但排序不一定足够精确。系统可以使用 Reranker 对候选文档进行二次评分，把真正相关的内容排在前面。

#### 上下文增强

系统将筛选后的资料和用户问题一起写入 Prompt：

```text
请只根据以下资料回答问题。如果资料不足，请明确说明。

资料：
{retrieved_documents}

问题：
{user_question}
```

大模型根据检索到的内容组织答案。需要注意的是，**RAG 并没有临时修改模型参数，只是为本次生成提供了额外上下文。**

## 三、为什么 RAG 有效

大语言模型擅长理解语言和组织答案，但不适合仅靠参数保存所有私有、实时知识。RAG 将能力拆分为两个部分：

| 组件 | 负责的能力 |
| --- | --- |
| 检索系统 | 找到准确、实时、可追溯的知识 |
| 大语言模型 | 理解问题、综合资料、生成自然语言答案 |

这种分工使知识可以独立更新，也能在答案中提供资料来源。

## 四、RAG 与微调的区别

| 对比项 | RAG | 微调 |
| --- | --- | --- |
| 主要作用 | 注入外部知识 | 调整模型行为和表达方式 |
| 知识更新 | 更新知识库即可 | 通常需要重新训练 |
| 可追溯性 | 可以引用来源 | 很难说明知识来源 |
| 适合场景 | 企业知识库、实时资料、文档问答 | 固定格式、风格、特定任务能力 |

如果目标是让模型知道最新业务资料，优先考虑 RAG；如果目标是让模型稳定遵循特定输出方式，可以考虑微调。两者也可以组合使用。

## 五、RAG 常见失败原因

RAG 的答案质量取决于整条链路，而不只是大模型。

1. **文档解析失败**：表格、图片或扫描 PDF 中的关键信息没有被正确提取。
2. **分块不合理**：检索到的片段缺少上下文，无法支持完整答案。
3. **用户问题表达模糊**：原始问题不适合直接检索，需要查询改写。
4. **召回不足**：相关文档没有进入候选集合。
5. **排序错误**：无关内容占据了有限的上下文空间。
6. **Prompt 约束不足**：模型忽略资料，转而根据参数知识回答。
7. **知识库内容冲突**：多个版本的资料同时存在，缺少时间或权限过滤。

因此，评价 RAG 系统时应分别观察召回率、排序质量、上下文相关性、答案忠实度和引用准确性。

## 六、常见优化方法

- 使用语义分块，保留标题和上下文关系
- 结合关键词检索与向量检索，形成混合检索
- 对用户问题进行改写、拆分或扩展
- 使用 Reranker 对召回结果重新排序
- 根据用户身份和元数据过滤文档
- 要求模型仅基于资料回答，并返回引用来源
- 对检索结果和最终答案分别建立评测集

## 总结

RAG 的本质不是让大模型记住更多内容，而是建立一条可靠的“查资料再回答”链路：

```text
知识入库 -> 问题检索 -> 内容筛选 -> 上下文增强 -> 答案生成
```

当资料能够被正确解析、召回和排序时，RAG 可以显著提升回答的准确性、时效性与可追溯性。
